## 接入步骤

1. 核对主站 PROJECT_HANDOFF/README、版本状态和既有离线输出路径，记录 FINAL 基线与备份。若存在未提交改动，保留并隔离，不覆盖。
2. 提取实际字体、色彩、网格、间距、卡片与图片比例；只在新模块中映射视觉参数。
3. 保持 development-module 根容器、dev- 样式、局部事件和脚本作用域。既有全局样式与业务逻辑不随意调整。
4. 在备份/隔离副本加入章节入口和模块，按实际主站构建方式接入数据和资产；不提前指定前端框架、数据库或托管方案。
5. 面向 Pro 用户生成一份“趋势主站 + AI 鞋款模块”的统一离线包和统一入口；后台上传页面不进入交付包。Standard 另行生成不含本模块的版本，资源收集与 PDF 输出同时执行权益筛选。
6. 对照 FINAL 核心浏览路径和视觉验收。通过并由用户确认后，再形成用于工厂演示的正式版本，保留独立原型和回退点。

## Standard / Pro 构建规则

| 输出 | Standard | Pro |
| --- | --- | --- |
| HTML | 仅趋势内容 | 趋势 + 已通过 Gate 的 Development |
| JSON/脚本数据 | 不含开发款私有数据 | 仅包含本期审核款 |
| PDF | 趋势版 | 趋势 + 对应开发资料 |
| 图片资产 ZIP | 本期基础趋势资产 | 本期趋势资产 + 对应开发资产 |

Standard 不携带隐藏的 Pro 原图、BOM、数据或 PDF；如需营销预览，另行制作并确认允许公开的示意素材。不能把 Pro 内容放入 Standard 包后只隐藏按钮。Pro 离线包只收集 `published` 款式及其引用图片；`unpublished` 与 `draft` 数据和资产不进入交付包，也不能仅靠前端筛选隐藏。

三个鞋型品类对所有 Pro 订阅用户默认开放。品类筛选只是浏览工具，不作为不同购买档位或访问权限；本阶段不建立按品类付费或授权的分支。

既有离线登录/密码方式需在实际集成时核对和回归，不重构为新的账号系统。本期不将登录界面描述为不可复制的授权保护，也不增加在线支付。

## 离线资源与输出

以本地资产和相对路径交付；字体、图标和所有必需图片也需能离线读取。页面不得依赖 CDN、远程图片或线上接口才能阅读核心内容。网络来源链接可保留作引用，不替代实际文件。

JSON 源文件独立保存；离线构建阶段选择嵌入数据或兼容的本地数据容器，并在直接打开 HTML 场景验证。桌面断网阅读、文件夹搬移、解压后打开与中文路径均纳入后续验收。

PDF 由同一发布数据生成，展开交互内容，逐页检查鞋图、标注、BOM、Gate 与待确认项。输出流程待原型之后实现，不将浏览器打印成功视为排版通过。

图片 ZIP 包含本期引用且允许交付的原始/展示图片（规格待确认），按款号、版本、视角或用途组织。清单记录 asset_id、style_id、revision、相对路径、用途、来源、使用状态、字节数和 SHA-256。完整性至少检查文件数量、哈希、文件可解码及引用匹配；不得打包只有网址的空清单充作图片交付。

## 回退与范围管理

集成有冲突时回到隔离副本修复，保持 FINAL 基线可恢复；不删除旧包或覆盖原图。未通过 Gate 的款保留在工作区，不进入正式 Pro 包。若工厂要求新工程、量产规格或更多款式，另行记录范围变更并与用户确定，不默默并入本期。
